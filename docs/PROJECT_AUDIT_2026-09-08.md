# 프로젝트 기능 점검 — 2026-09-08

## 범위

기존 코드 관계 그래프를 출발점으로 프로젝트 저장·불러오기·복구, 미디어 재연결,
플레이리스트와 가사 처리, 편집 이력, 미리보기와 내보내기 관련 코드를 검토하고
34개 테스트 모듈을 실행했다. 실제 사용자 프로젝트의 장시간 편집, GPU별 렌더링,
설치·업데이트 서버와의 실연동까지 검증한 것은 아니다.

## 적용한 개선

| 영역 | 재현한 문제 | 수정 |
| --- | --- | --- |
| 복구 목록 | 복구 JSON의 루트가 배열·null·문자열이면 예외가 전파되어 정상 복구 파일도 조회하지 못함 | 객체 여부를 검증하고 기존 손상 파일 건너뛰기 경로로 처리 |
| 복구 순서 | 시간대 없는 시각과 UTC 시각이 섞이면 정렬 실패 | 시간대 없는 복구 시각을 UTC로 해석 |
| 프로젝트 입력 | 빈 객체·문자열이 소스·트랙 목록으로 허용되거나, 잘못된 settings가 시작 화면용 검사에서 AttributeError 발생 | 목록은 배열인지 확인하고 잘못된 settings는 ProjectError로 보고 |
| 미디어 연결 | 프로젝트 상대 경로보다 실행 폴더의 동명 파일을 먼저 선택 | 상대 경로는 프로젝트 폴더를 우선 확인하고 기존 대체 경로 유지 |

새 회귀 테스트로 수정 전 실패를 확인하고 수정 후 관련 테스트 18개 통과를 확인했다.
프로젝트 파일 형식과 내보내기 알고리즘은 변경하지 않았다.

## 검증과 한계

- Python 3.12 빌드 가상환경에서 compileall과 git diff --check 통과.
- 기본 `.venv` 실행 파일은 프로세스를 시작하지 못하여 `.build-venv312`를 사용.
- 파일별 테스트 결과: 루트의 `audit-module-results.log`.
- 기능 회귀 모듈은 사용자 데이터 저장 경로에서 지연되었다. QStandardPaths의 저장
  경로를 임시 디렉터리로 격리한 재실행에서 96개 모두 통과했다.
- 언어팩 모듈은 첫 실행에서 검사 완료 후 비정상 종료했으나 재실행은 6개 통과하고
  정상 종료했다. 최초 종료 오류의 근본 원인은 확정하지 않았다.
- 실제 FFmpeg·영상 성능 관련 선택 테스트 9개는 실행 조건 미설정으로 건너뛰었다.
- 메인 창 모듈은 저장 경로 격리 후에도 45초 제한을 초과했다. 당시 스택은 테마 변경
  테스트의 `_apply_style` 실행을 가리켰다. 느린 실행인지 상태 누적인지는 미확정이며
  전체 모듈 통과로 집계하지 않았다. 진단은 `audit-main-window-isolated-data.log`에 기록.
- offscreen 테스트로 화면의 실제 배치나 GPU별 표시 품질까지 보장할 수는 없다.

## 큰 변경 전 논의할 후보

1. **메인 창의 작업 제어 분리**: `app/ui/main_window.py`가 저장, 복구, 내보내기,
   작업 종료와 UI 상태 갱신을 함께 담당한다. 먼저 저장·복구 제어만 별도 객체로
   옮기면 검토 범위를 줄일 수 있다. 신호 연결과 비동기 작업 완료 순서가 바뀔 수
   있으므로 기존 동작을 유지하는 단계적 변경으로 진행하는 것을 권장한다.
2. **실행 취소 메모리 비용 측정**: HistoryService는 프로젝트 전체 JSON 복사본을
   최대 100개 유지하고, 복원 시 프로젝트를 다시 적용한다. 대형 가사·레이어 프로젝트의
   메모리와 편집 지연을 측정한 뒤 필요할 때 변경분 저장을 검토한다. 지금 바로
   명령 기반 실행 취소로 바꾸는 것은 복원 정확도에 대한 위험이 더 크다.
3. **테스트 데이터 경로 격리**: UI 테스트가 실제 사용자 데이터 경로에 의존하는 부분을
   임시 저장소로 통일하고 종료 시 Qt 객체 정리를 검증한다. 렌더링 로직 변경보다
   먼저 테스트의 재현성을 높이는 작업이 적절하다.

위 구조 변경은 이번 점검에서 적용하지 않았다.
